# Список дел: Express и база данных
Решил делать через яндекс клауд: API Gateway как прокси -> Serverless Containers как сервер -> MongoDB Atlas как бд
## Ход работы
Начинаем с express-приложения локально. Создаём папку, туда инициализирую npm (Node Package Manager) (менеджер пакетов для nodejs, который устанавливает библиотеки) `npm init -y`, далее скачиваем `npm install express uuid mongoose dotenv`:
* express - собственно фреймворк
* uuid - генерирует уникальные ID для задач
* mongoose - драйвер для работы с MongoDB, связывает код с базой данных: позволяет описать, как выглядит задача (модель), и делать запросы (создать, найти, обновить, удалить). Благодаря ему данные реально сохраняются в БД и остаются там после перезапуска сервера.
* dotenv - позволяет хранить секретные данные (адрес базы, токен, логин) не в коде, а в отдельном файле .env

В Windows такого ядра нет, поэтому Docker не может просто так запустить контейнер. Ему нужен слой, где это ядро есть. Для него также необходимо установить `wsl --install` - WSL2 (Ubuntu внутри Windows)

Перезагрузил комп. Включаю докер.

Установил Yandex Cloud CLI - инструмент для управления ресурсами облака через командную строку. С помощью него можно создать Container Registry, это место в облаке, куда докер загрузить образ приложения.

Выполняю команды:
```
# создаю реестр
yc container registry create --name tasks-registry
# на выходе id реестра

# настраиваю docker-клиент на авторизацию в Яндексе
yc container registry configure-docker

# собираю и отправляю образ
docker build -t cr.yandex/<REGISTRY_ID>/tasks-app:latest .
docker push cr.yandex/<REGISTRY_ID>/tasks-app:latest
```
В облаке теперь лежит образ

Далее создаю контейнер в Serverless Containers. Там выбираю появившийся образ (latest). Ставлю переменные кроме порта. Таймаут исполнения — 15. ## Краткий анализ размещения БД
### MongoDB Atlas (используемый вариант)
СУБД: MongoDB (облачная управляемая СУБД класса DBaaS).

Тариф: постоянный бесплатный тариф M0 — это именно free tier без ограничения по сроку, а не пробный период. Оплата кластера M0 — 0 ₽ навсегда; платные тарифы начинаются примерно от 8–9 $/мес за кластер M10. 

Ограничения хранения и подключений: объём хранилища — 512 МБ, максимум 500 одновременных подключений, один бесплатный кластер M0 на проект, общая RAM и vCPU (shared), автоматические резервные копии не предусмотрены, ограничение скорости CRUD-операций (около 100 операций в секунду). 

Результат собственной проверки доступности (07.11.2026): кластер создан и доступен — приложение подключается к БД как локально, так и из контейнера в Yandex Cloud (в логах фиксируется успешное подключение к MongoDB). В Access List задан доступ 0.0.0.0/0. Данные (задачи) сохраняются между перезапусками приложения — персистентность подтверждена тестами Postman.
### Yandex Cloud 
СУБД: сервис Yandex StoreDoc (Managed Service for DocumentDB) — полностью MongoDB-совместимая документоориентированная NoSQL-СУБД. 

Тариф: постоянного бесплатного тарифа для этой СУБД нет — она не входит в перечень сервисов с free tier (бесплатный уровень Yandex Cloud охватывает 21 сервис: Compute Cloud, Object Storage, Cloud Functions, API Gateway, YDB и другие, но не StoreDoc/MongoDB). Оплата — по модели pay-as-you-go за фактически потреблённые ресурсы: класс хостов (vCPU и RAM за час работы) и объём хранилища.
