# Практическое задание 2
## Образование
АПИ - контракт коммуникации с системой. Разработчикам систем необходимо предоставлять потребителям системы информацию об АПИ - появилась задача на документацию АПИ. 

Сначала все делали по-своему, но далее выявили определённый стандарт - OpenAPI. Им начали описывать АПИ до начала разработки. Существует множество интересной исторической информации о стандарте.

Свойство стандарта - наличие структуры. Доступные языки стандарта JSON и YAML. Стандарт, его структура состоит из переменных / секций и их значений. Переменные имеют строгий порядок и характеристику обязательности:
1. openapi - первая обязательная переменная, номер версии спецификации OpenAPI.
   1. Если не указать, то валидатор (например, Swagger Editor) покажет ошибку, интерактивная документация (например, Swagger UI) не создастся, генератор кода даст ошибку (например, OpenAPI Generator, Swagger Codegen).
   2. Если указать одну версию, а в описании использовать синтаксис стандарта предыдущих или последующих версий, то инструменты (валидаторы, генераторы кода, документации, генераторы кода) проигнорируют синтаксис отличной версии или вернут ошибку.
2. info - вторая обязательная переменная, справочная информация о документе. Имеет:
   1. Обязательные переменные: title (заголовок) и version (версия документа)
   2. Необязательные переменные: description, termsOfService, contact, license
3. servers - третья необязательная переменная, список серверов-адресатов АПИ-запросов. Если не указано, то значит адрес сервера не определён. Состоит из:
   1. url - обязательная переменная, адрес сервера. Может быть множество url, например, тестовый и промышленный. Может содержать переменные в {} (например, https://{host}/v1).
   2. description - необязательная переменная, описание url.
   3. variables - описание переменных {} из url, обязательная переменная, если переменные содержаться в url. Состоит из:
      1. (Название переменной из {} url'а) - обязательная. Имеет:
         1. default - обязательная переменная, значение переменной по умолчанию
         2. enum - необязательная переменная, список допустимых значений, должен иметь значение по умолчанию. При наличии пользователь сможет отправить запрос только с значением из списка
         3. description - необязательная переменная, описание переменной
4. paths - обязательная переменная, описание АПИ-методов. Состоит из:
   1. /(название метода). Состоит из:
      1. Тип метода: get, post, put, patch, delete, head, options, trace, query (появился в OpenAPI 3.2). Подробнее прочитать про каждый возможно в открытых источниках при поиске "Типы HTTP-методов" Имеет:
         1. responses — обязательная переменная, список возможных ответов. Состоит из:
             1. Код ответа (от 100 до 599). Состоит из:
                1. description — обязательная переменная, описание ответа
                2. content — необязательная переменная, карта медиатипов (application/json, text/html и т. д.). Состоит из:
                   1. Медиатип (ключ, например application/json). Состоит из:
                      1. schema — необязательная переменная, схема данных ответа. Состоит из:
                         1. type - обязательная переменная, формат ответа
                         2. properties - обязательная переменная, если type: object, свойства ответа (его переменные). Состоит из:
                            1. Название свойства. Состоит из:
                               1. type - обязательная переменная, формат переменной
                               2. format - необязательная переменная, формат переменной (например, password, email, date для string)
                               3. example - необязательная переменная, пример переменной
                      3. example — необязательная переменная, пример ответа целиком
                         1. Название переменной - значение
                      5. examples — необязательная переменная, несколько именованных примеров. Состоит из:
                         1. Имя примера. Состоит из:
                              1. summary — необязательная переменная, краткое описание примера
                              2. description — необязательная переменная, подробное описание примера
                              3. value — необязательная переменная, само значение примера
                              4. externalValue — необязательная переменная, ссылка на пример (URL)
                      6. ?encoding? — необязательная переменная, правила кодирования для multipart. Состоит из:
                         1. Имя свойства. Состоит из:
                            1. contentType — необязательная переменная, MIME-тип части
                            2. headers — необязательная переменная, заголовки части. Структура как headers в ответе (см. ниже)
                            3. style — необязательная переменная, стиль сериализации
                            4. explode — необязательная переменная, разделение массивов через запятую
                            5. allowReserved — необязательная переменная, разрешить зарезервированные символы
                3. headers — необязательная переменная, заголовки ответа. Состоит из:
                   1. Имя заголовка. Состоит из:
                      1. description — необязательная переменная, описание заголовка
                      2. schema — необязательная переменная, тип данных заголовка
                      3. required — необязательная переменная, обязателен ли заголовок
                      4. deprecated — необязательная переменная, флаг устаревания
                      5. style — необязательная переменная, стиль сериализации
                      6. explode — необязательная переменная, в каком виде передавать массив
                      7. allowReserved — необязательная переменная, разрешать ли зарезервированные символы без кодирования
                      8. example — необязательная переменная, пример значения
                      9. examples — необязательная переменная, несколько именованных примеров (структура как в content)
                4. links — необязательная переменная, связи с другими операциями. Состоит из:
                   1. Имя связи. Состоит из:
                      1. operationRef — необязательная переменная, ссылка на операцию (через $ref). Либо operationId, либо operationRef
                      2. operationId — необязательная переменная, ID связанной операции. Либо operationRef, либо operationId
                      3. parameters — необязательная переменная, карта подстановки параметров (через Runtime Expression, например $response.body#id)
                      4. requestBody — необязательная переменная, тело запроса для связанной операции (Runtime Expression)
                      5. description — необязательная переменная, описание связи
                      6. server — необязательная переменная, сервер для связанной операции (структура как в корневом servers)
          2. summary — необязательная переменная, короткое название операции
          3. description — необязательная переменная, подробное описание операции, поддерживает Markdown
          4. operationId — необязательная переменная, уникальный идентификатор операции
          5. tags — необязательная переменная, массив строк для группировки в документации
          6. parameters — необязательная переменная, массив параметров запроса. Состоит из:
             1. Параметр. Имеет:
                1. name — обязательная переменная, имя параметра
                2. in — обязательная переменная, расположение: path, query, header, cookie
                3. required — необязательная переменная, обязателен ли параметр. Для in: path всегда true
                4. schema — необязательная переменная, тип данных и правила валидации
                5. description — необязательная переменная, описание параметра
                6. example — необязательная переменная, пример значения
                7. examples — необязательная переменная, несколько именованных примеров (структура как в content)
                8. style — необязательная переменная, стиль сериализации (form, simple, label, matrix)
                9. explode — необязательная переменная, разделение массивов
                10. allowReserved — необязательная переменная, разрешить зарезервированные символы без кодирования
                11. deprecated — необязательная переменная, флаг устаревания
          7. requestBody — необязательная переменная, тело запроса. Состоит из:
             1. content — обязательная переменная, карта медиатипов (структура как content в responses)
             2. description — необязательная переменная, описание тела запроса
             3. required — необязательная переменная, обязательно ли тело. По умолчанию false
          8. security — необязательная переменная, требования безопасности для операции. Массив объектов вида "имя схемы: [scopes]"
          9. servers — необязательная переменная, переопределение серверов для операции (структура как в корневом servers)
          10. deprecated — необязательная переменная, флаг устаревания (boolean). По умолчанию false
          11. externalDocs — необязательная переменная, ссылка на внешнюю документацию. Состоит из:
              1. url — обязательная переменная, ссылка
              2. description — необязательная переменная, описание ссылки
