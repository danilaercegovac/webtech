* Установил Flask `pip install Flask`. Flask - фреймворк на питоне для написания веб-приложений. Имеет много плюсов. В интернете его хвалят. Питон мне ближе чем что либо, выбираю его для решения задачи (обучаюсь ему из этого [пособия](https://habr.com/ru/companies/otus/articles/886390/))

* `from flask import Flask` - достаю класс Flask, непосредственно то, что есть веб-приложение
* `app = Flask(__name__)` - делаем экземпляр веб-приложения. Почему указываем `__name__`. `__name__` - специализированная встроенная переменная в питоне. Она даёт информацию о местоположении текущего файла, его модуля, то есть родительской папки. Нужно это, чтобы иметь информацию о местоположении необходимых папок с, например, шаблонами или стилями.
* Flask имеет удобный способ указывать пути для приложения и определять для них поведения. Объявляется путь конструкцией `@app.route("/")`. Данная конструкция имеет термин - декоратор. Он типо обёртывает функцию, которая должна идти сразу следом, в другую функцию. Декораторы - тема не очевидная. Здесь суть декораторов объясняется не показательно. По факту, лучшее объяснение здесь, что Flask имеет внутреннюю таблицу для маршрутизации. Через `@app.route("/")` Flask создаёт-запоминает новый путь, а функцию после нее запоминает, чтобы вызвать, когда пользователь пройдет по пути.
* Указываем путь, эксперимента ради, для главной страницы
```
@app.route("/")
def home():
    return "Привет, мир! Flask работает!"
```
И тогда, перейдя по маршруту "/", пользователь увидит страницу с текстом "Привет, мир! Flask работает!" на ней. То есть Fast тем удобен, что он берёт на себя всю логику по принятию и отдаче http запроса, ответа. Здесь, что меня удивило, что мне было достаточно написать некую строку, чтобы она отобразилась браузером, то есть по факту как html. Дело в том, что Flask по умолчанию указывает в заголовке `Content-Type: text/html; charset=utf-8`. Браузер получает html, но не видит никаких тегов, пробует отобразить всё равно строку как html и отображает строку. curl запрос вернёт чисто строку. Если хотим поменять по умолчанию html формат, то нужно так сделать `return Response("Привет, мир! Flask работает!", mimetype="text/plain")`
* Осталось запустить, но увидел важный момент, что нужно проверять откуда приложение исполняется. Нужно, чтобы сервер запускался только, когда файл запускается непосредственно сам. А как он ещё может запуститься? Здесь интересный момент про библиотеки и импортирование существующих файлов. Когда мы что-то импортируем, мы используем, задействуем написанный код в библиотеке. Если вызвать наш файл через, например, `from app import app`, то мы по факту запустим выполнение кода файла. И то есть нужно как-то избежать того, что условно к нашему файлу обратятся, и сервер случайно запустится. Здесь придумано следующее, в нашем файле запускаем сервер не сразу же, а с условием. Условие должно быть таково, что код исполняется при запуске непосредственно программы, а не вызывается кем-то. Для этого питон-интерпретатор наделяет запускаемым файлам имя `__name__`. Если запускается непосредственно программа, то `__name__` приобретает значение `__main__`, а если файл импортируется, то файл приобретает `__name__ == "имя файла":`. Поэтому делаем условие перед запуском сервера:
```
if __name__ == "__main__":
    app.run(debug=True)
```
`debug=True` здесь даёт режим откладки. Типо меняем код, он сразу на сервере обновляется, не надо перезапускать сервер. А ещё даёт больше инфы в консоли. Короче полезно во время разработки.
* Далее сохраняем и собственно запускаем. Выбираем папку, где программа, в консоли `cd /путь/к/папке`. И python app.py. С базой закончили, переходим непосредственно к решению задачи
