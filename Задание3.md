## Описание работы
### Промис. Общая инфа
Хочется освежить в памяти тему промисов, а не бездумно сгенерировать код с ии.

Промис - инструмент получения асинхронного ответа в коде. Некоторые процессы, например, вызовы АПИ требуют время для выполнения, но код JS работает последовательно, однопоточно, и если бы не было промисов, то код бы останавливался, следовательно, и веб-страница, пока код дождётся ответа от, например, апи вызова.
Промисы же позволяют запустить асинхронный процесс получения ответа, чтобы не останавливать основной процесс, чтобы мочь обратиться к результату промиса (например, апи вызова) спустя время, когда асинхронный процесс закончится.

Промисы имеют три типа состояния:
* pending — ожидание (промис ещё не завершился);
* fulfilled — успешно завершён;
* rejected — ошибка.

В JavaScript существует конструктор Promise, который создаёт объекты-промисы.
```
// Создаём через конструктор новый промис
const myPromise = new Promise((resolve, reject) => {
  // Здесь выполняется асинхронная операция
  if (успешное выполнение) {
    resolve(result);
  } else {
    reject(error);
  }
});
```
`(resolve, reject) => { ... }` - функция-исполнитель, которая начинает работу синхронно, сразу после создания промиса. resolve, reject - это колбэки, которые вызываются. resolve меняет состояние промиса на `fulfilled`, а reject на `rejected`, результат/ошибка становятся значением промиса. Существуют методы обращения к результатам промиса, методы обработки:
* .then - метод обработки двух состояний: fulfilled и rejected. Но принято, говорят в интернете, чтобы .then использовался только для успешного сценария, но всё же покажу как его использовать для обоих сценариев.
```
myPromise.then(
  result => действие 1,
  error  => действие 2
);
```
Если промис завершился успешно, то выполнится первая строка действия метода .then. Если неуспешно - действие 2. Здесь нет привязки к названиям 'result' или 'error', здесь учитывается только порядок. Посредством 'result' или 'error' в методе называются переменные для значений, которые были переданы в resolve(), reject() => Значит, чтобы обратиться к этим значениям нужно использовать объявленные названия. Например, `result => console.log('Успех:', result)`.

Управляет очередью действий движок JS. Его логика такая, что когда синхронные операции кода закончены, когда синхронный стек пуст, некая механика Event Loop смотрит в очередь микрозадач, в которой могут оказаться колбеки. И, непосредственно, объявление метода .then() выполняет регистрацию колбека. Не запускает его сразу! Колбэк уходит в очередь микрозадач (или туда, где движок держит такие задачи). Поэтому после объявления метода сначала выполнится весь синхронный код после объявления, а потом уже и колбек промиса.

Смежная заметка. Объявление result/error, что в примерах, есть непосредственно объявление аргументов. Их можно указать в скобках, можно без, ибо они в единственном числе. Когда 2+ аргументов, необходимо аргументы писать в скобках через запятую. Также кусок '=> действие 1' показывает правило неявного return, что значит, что если операция функции единственна, то можно не указывать {} после `=>`, за return считается результат единственной операции. Но если операций больше, то нужны {}, а операции через точку с запятой

Ещё одна смежная заметка. Можно писать методы к функциям сразу после их объявления типо:
```
task().then()
task().catch()
```
А можно иначе:
```
task()
  .then()
  .catch()
```
Для JS это не ошибка. Это типо красивее читабельнее.

* .catch() - метод обработки неуспешного колбека промиса (reject)
### Промис. Функция из задания
Задание требует вывод такой функции
```
function task(x) {
  return new Promise((resolve, reject) => {
  if (x < 18) {
    resolve('yes');
  } else {
    reject('no');
  }
});
}
```
В одну строку это будет 'function task(x) {\n  return new Promise((resolve, reject) => {\n  if (x < 18) {\n    resolve('yes');\n  } else {\n    reject('no');\n  }\n});\n}'. Но это делать необязательно. В YAML символ | используется для указания многострочного текста. Итого новый путь выходит таким:
```
  /promise:
    get:
      x-yc-apigateway-integration:
        type: dummy
        content:
          '*': |
          function task(x) {
            return new Promise((resolve, reject) => {
              if (x < 18) {
                resolve('yes');
              } else {
                reject('no');
              }
            });
          }
        http_code: 200
        http_headers:
          Content-Type: text/plain; charset=utf-8
          Access-Control-Allow-Origin: "*"
```
Поймал ошибку `"message": "Invalid openapi spec: while scanning a simple key\n in 'reader', line 41, column 11:\n function task(x) {\n ^\ncould not find expected ':'\n in 'reader', line 49, column 11:\n }\n ^\n\n at [Source: (StringReader); line: 41, column: 1]",
"code": "GATEWAY_REQUEST_ERROR",
"title": "Ошибка",`

Важно. Используя | в YAML, главное соблюсти корректность отступов, чтобы строки после | не начинались раньше '*'. В моём описании они как раз сдвинуты на один таб. Передвинул вперёд - получилось без ошибок.

#### HTML детали
Касаюсь написания фронта изредко, отчего быстро забываю некоторые вещи, но быстро вспоминаю. Запишу их, чтобы лучше запомнилось:
* `document` - главный объект html-страницы, представляет весь HTML‑документ как дерево элементов (DOM). Даёт:
  * Быстрый доступ к ключевым частям страницы
    * document.title — заголовок вкладки (содержимое <title>).
    * document.body — элемент <body>, основная часть страницы.
    * document.head — элемент <head>.
    * document.documentElement — корневой элемент, то есть <html>.
  * Поиск элементов (самый частый сценарий). Через document ищут элементы, чтобы с ними работать:
    * document.getElementById('id') — найти по уникальному id.
    * document.getElementsByClassName('class') — по классу (возвращает «живую» коллекцию).
    * document.getElementsByTagName('div') — по тегу.
    * document.querySelector('.class') — первый элемент по CSS‑селектору.
    * document.querySelectorAll('.class') — все элементы по селектору (возвращает NodeList).
  * Создание и вставка элементов
    * document.createElement('div') — создать новый элемент.
    * document.createTextNode('Текст') — создать текстовый узел.
    * document.createDocumentFragment() — фрагмент для эффективной вставки нескольких элементов.
  * Информация о состоянии документа
    * document.readyState — статус загрузки: "loading", "interactive", "complete".
    * document.URL / document.location.href — адрес текущей страницы.
    * document.referrer — откуда пришёл пользователь (если браузер передал реферер).
    * document.cookie — куки текущей страницы
  * Доступ к метаданным и коллекциям
    * document.scripts — коллекция всех <script> на странице.
    * document.links — все ссылки (<a> с атрибутом href).
    * document.forms — все формы на странице.
  * Можно добавить .addEventListener на страницу
